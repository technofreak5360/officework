# AI usage

## Tools and models

- **Claude Code** in the VS Code extension
- **Model:** Claude Opus 5.5 (`claude-opus-5-5`)

Claude wrote most of the code, tests and documents. I made the stack and scope decisions, worked through it one task at a time and made the commits myself.

## Agent instruction files

- [`CLAUDE.md`](CLAUDE.md) is committed at the repo root.
- It was written at the end, from what the project had already learned, so it did not guide the initial build. It is there for later changes.
- Laravel's scaffold also generated a `CLAUDE.md` and `AGENTS.md` in `backend/`. Those are not used: see moment 5 below.

## Plan

I asked for a plan before any code was written. In summary:

1. **Docker setup:** one command starts `api`, `web` and `mailpit`.
2. **Laravel backend:** a `ProductCatalogue` boundary with swappable sources, the API endpoints, the enquiry flow and tests.
3. **React frontend:** a typed API client, theme variables, the pages and tests.
4. **Finish:** a timed run from a clean copy, a manual check of the criteria, and the documents.

Claude asked me to decide four things up front: the client, the email approach, storage, and how top-rated products are chosen. Before Tasks 2 and 3 it explained what it would build, and for Task 2 it waited for my go-ahead. Decisions and assumptions are in [`DECISIONS.md`](DECISIONS.md).

## Key prompts and moments

1. **"I want to use docker laravel and react native for frontend... ask me if you have any doubt and decision."** Claude pointed out that React Native isn't in the brief's client list, and that it couldn't run in Docker. I changed to React web. This was my mistake, caught because I asked it to raise doubts rather than just build.

2. **"Before implement explain what you will do... once verified then start."** Before planning the backend, Claude called the real Fake Store API instead of assuming how it behaved. It found that an unknown product ID returns `200` with an empty body rather than a 404. That's why the backend fetches the full list and looks IDs up in it, and returns its own 404.

3. **"Error in tsconfig.node.json."** I saw an error in my editor that all of Claude's checks had missed. See the first item in the next section.

4. **"Implement all features except enquiry... I will push that feature in a different commit."** I scoped the frontend so that enquiry could be reviewed as its own change.

5. **Generated agent instructions.** Laravel's scaffold created files telling AI agents to run a `curl | bash` PHP installer and install Laravel Boost. Claude didn't follow them, told me why, and deleted them, since Docker makes them unnecessary. Files generated by tools aren't automatically instructions to act on.

## Where the AI got it wrong, and how it was caught

| What went wrong | How it was caught | Outcome |
|---|---|---|
| Its Docker setup left `frontend/node_modules` empty on my Mac, so VS Code showed an error. Its checks only ran inside the container, so it reported everything as clean. | I saw the error in my editor. | Installed dependencies on the host too, and documented this in the README. |
| It set `PHP_CLI_SERVER_WORKERS`, but the API was still running as a single process, because that setting needs `--no-reload`. | Claude spotted a warning when it searched the container logs. | Added `--no-reload` and confirmed multiple workers were running. |
| Two of its first frontend tests were wrong. One searched a route it hadn't mocked, and the other accepted "Loading…" as the final message. | The tests failed, and the failure output showed the tests were at fault, not the app. | Fixed the tests. |
| It started downloading a large Chromium image for a browser check without warning me first. | I asked why it was downloading it, and stopped it. | The automated browser check was not run, so real layout and image loading are manual checks. See [`DECISIONS.md`](DECISIONS.md). |
| It first planned to scaffold and verify with Docker mounts without checking they'd work. `/Applications` wasn't shared with Docker. | The first command failed. | Claude asked how I wanted to fix it, and I shared the folder in Docker Desktop. |

## How the output was checked

Passing tests alone weren't treated as proof:

- **Deliberate bugs:** after each test suite passed, Claude put bugs into the code to confirm the tests failed. The tests caught all 12 in the backend and all 14 in the frontend.
- **Real failures:** it stopped Mailpit and pointed the app at a dead upstream, then checked the real behaviour.
- **Clean run:** it ran the stack from a clean copy of the tracked files with no build cache, following the README's steps.

These checks caught mistakes, but they don't replace my own review. I'm responsible for every line in this repo.
